# Playbook 06 — Release ke GitHub Pages

Ini panduan, bukan bukti website telah dipublikasikan.

## Prarelease

- Pastikan repository/site target, visibility, plan dan biaya sesuai instruksi.
- Bedakan knowledge repo portofolio-web dari user site username.github.io.
- Baca ketentuan Pages terkini serta output stack.
- Review facts, media rights, secrets dan third-party resources.
- Build output dan jalankan gates relevan.

## Publish

Pilih branch/folder atau Actions sesuai kebutuhan. Konfigurasi base URL/project subpath. Permissions minimum. Jangan mengunggah source yang membutuhkan server runtime. Tindakan publishing mengikuti scope otorisasi.

## Post-deploy

Verifikasi actual URL: HTML, CSS/JS/media, direct detail, reload, anchor, 404, kontak, CV, HTTPS, metadata dan responsive states. Commit/tool success tidak menggantikan browsing hasil.

## Recovery

Jika deploy hasilnya tidak diketahui, baca status sebelum retry. Jika release rusak, pilih revert/previous valid output dengan alasan, publish dan recheck. Jangan force atau hapus history sebagai default.

## SEO

Title/description/canonical/sitemap berbasis domain final. Robots tidak mengamankan data. Preview caches external mungkin lambat; review page source dan renderer terpisah. Ranking tidak dijanjikan.
